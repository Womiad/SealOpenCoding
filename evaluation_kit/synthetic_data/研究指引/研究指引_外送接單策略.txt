# 研究目的
本研究想了解外送員如何決定接哪些單、避開哪些單：判斷依據（距離、金額、店家、時段、
天氣、地點安全）、曾經吃虧或學到教訓的具體事件，以及這些策略如何隨經驗與身分
（全職、兼職、日班、晚班、機車、汽車）而改變。不處理平台抽成與收入的具體數字，
也不推測派單演算法的內部運作方式。

# 角色與資料規則
逐字稿以「訪員：」與「受訪者：」標示。只有受訪者自己的實質經驗、想法、行為或評價
可以成為 code 的主要依據；訪員的提問、情境說明與重述只能作為理解上下文的材料。
受訪者轉述平台公告、客服說法或其他外送員的說法時，要與其本人的直接經驗區分開來。

# 優先尋找的行為模式
- 情境／觸發（一次事故、被放鳥、對帳不符）→ 行動或新規則 → 結果或代價，以及受訪者自己怎麼評價
- 有條件的接單規則：「超過…除非…才接」「只有…時段」「這種店我不接」
- 自己整理的土法：黑名單、截圖存證、先打電話確認、自建地址清單
- 為了安全或健康付出的代價，以及受訪者如何評價那個代價
- 說法與做法之間的矛盾，以及受訪者自己給的解釋（時段、身分、經驗）

# 可形成研究機會的訊號
- 想知道卻看不到的資訊（店家出餐速度、回程距離、正確大門位置）
- 被平台流程擋住、只能自力救濟的地方
- 對同一種單（遠距離高額單、雨天單、深夜單），不同受訪者給出相反判斷的地方
- 願意接受或明確拒絕某種單的條件

# 排除規則
- 平台抽成比例、時薪與收入的具體金額不作為 code（可提及，但不深究數字）
- 訪員的提問、功能介紹、重述與總結
- 「嗯」「對」「好」這類沒有內容的簡短回應
- 沒有理由也沒有具體經驗的一般背景敘述（例如只說跑了多久）

# Code 結構
每個 code 是一個能獨立閱讀的分析句，包含情境、受訪者的行動或理由，以及結果或意義。
不要只寫「挑單」，要寫「深夜偏僻地址曾被放鳥且聯絡不上，之後出發前一律先打電話確認，
受訪者認為一通電話省下一單的損失」。
