# 研究目的
本研究想了解一般人如何用穿戴裝置或手機 App 記錄自己的運動（跑步、重訓、走路、球類等）：
哪些數據會被看、看了之後改變了什麼做法；紀錄與分享如何影響持續運動的動力；
以及人們在什麼情況下停止紀錄、甚至停止運動。不評估任何裝置的量測準確度，
不比較品牌與價格，也不涉及疾病、診斷或醫療建議。

# 角色與資料規則
逐字稿以「訪員：」與「受訪者：」標示。只有受訪者自己的實質經驗、想法、行為或評價
可以成為 code 的主要依據；訪員的提問、情境說明與重述只能作為理解上下文的材料。
受訪者轉述 App 通知、官方說明或他人說法時，要與其本人的直接經驗區分開來。

# 優先尋找的行為模式
- 看到某個數據 → 調整行為 → 結果（更持久、受傷、失去樂趣、成績變化），以及受訪者自己怎麼評價那個結果
- 有條件的做法：「只有…才記」「如果斷了就…」「超過…我就…」
- 紀錄習慣的建立、中斷與放棄的具體過程（發生了什麼事、之後怎麼了）
- 對分享（貼到社群、給朋友看）自己劃出的界線與理由
- 憑感覺與看數據之間，受訪者自己劃的線

# 可形成研究機會的訊號
- 數據幫不上忙、或反而造成壓力與反效果的情況
- 想記卻記不到的東西（感受、狀態、天氣、脈絡）
- 對同一種數據（連續天數、心率、配速），不同受訪者給出相反用法或評價的地方
- 自動偵測、自動建議與使用者自己判斷之間的分界

# 排除規則
- 裝置規格、價格與品牌比較（本指引不處理）
- 涉及疾病、診斷或醫療建議的內容不作為 code
- 訪員的提問、功能介紹、重述與總結
- 「嗯」「對」「好」這類沒有內容的簡短回應
- 沒有理由也沒有具體經驗的一般背景敘述（例如只說運動了幾年）

# Code 結構
每個 code 是一個能獨立閱讀的分析句，包含情境、受訪者的行動或理由，以及結果或意義。
不要只寫「連續天數」，要寫「為了不讓連續天數斷掉，下雨天也出門快走十分鐘充數，
受訪者自認有一半是灌水，但認為至少讓自己持續出門」。
