# 研究目的
本研究想了解短影音創作者如何決定「要不要加音效與環境音、加什麼、加多少」，這些決定背後的判斷依據是什麼
（觀眾反應、自己的美學、時間成本），以及音效與畫面、配樂之間的關係如何被創作者理解。
不處理音樂版權與授權問題，也不處理配樂的選曲。

# 角色與資料規則
逐字稿以「訪員：」與「受訪者：」標示。只有受訪者自己的實質經驗、想法、行為或評價可以成為 code 的主要依據；
訪員的提問、情境說明與重述只能作為理解上下文的材料。
受訪者轉述客戶或觀眾的說法時，要與其本人的直接經驗區分開來。

# 優先尋找的行為模式
- 加音效的觸發情境（畫面太安靜、素材沒有現場聲、想營造某種空間感）→ 具體做法（加了什麼、音量如何處理）→ 觀眾或客戶的反應
- 自己劃出的界線與比喻（例如「調味料」「補畫面沒講清楚的東西」）
- 加太多之後的教訓與收斂
- 音效是否向客戶或觀眾說明；不說明的理由
- 對「音效 vs 對節拍」時間分配的取捨

# 可形成研究機會的訊號
- 創作者說不清楚但觀眾有感的效果（例如門鈴聲讓人覺得「有人住」）
- 想做卻缺乏素材或工具的情況
- 不同受訪者對音效角色的相反判斷

# 排除規則
- 配樂版權、授權、下架與平台檢舉相關內容（本指引不處理）
- 訪員的提問、功能介紹、重述與總結
- 「嗯」「對」「好」這類沒有內容的簡短回應
- 沒有理由也沒有具體經驗的一般背景敘述

# Code 結構
每個 code 是一個能獨立閱讀的分析句，包含情境、受訪者的行動或理由，以及結果或意義。
不要只寫「音效」，要寫「客戶素材無現場聲看起來像型錄，於是鋪上低音量的門鈴與車聲，留言開始出現『像在他家』」。
