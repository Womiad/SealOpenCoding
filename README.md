# 海豹牌 Open Coding 工具（Seal Open Coding）V1.3

把一份研究指引（研究背景、研究問題、想找的現象或 sensitizing concepts）與一份或多份訪談逐字稿交給本機 Ollama。程式會為每份逐字稿各產生一個 CSV。

CSV 欄位包括：來源檔、句子 ID、原始行號、說話者、原句全文、精確證據短句、code、判斷理由、`why_this_code`、信心分數。每個 code 各佔一列，`why_this_code` 會分別說明原句中的哪個意思支持該 code。模型必須提供存在於原文的精確證據，程式會用證據反查真正段落，再從來源檔填回原句；無法在原文定位的結果會被拒絕，不會誤套到第一段。

## 需求

- Python 3.10+
- [Ollama](https://ollama.com/) 與一個已下載的模型
- 輸入格式：`.txt`、`.md`、`.docx`

目前預設使用這台電腦已安裝的 `qwen3:8b`。若另有更大的中文指令模型，可用 `--model` 切換；模型品質會直接影響 coding 品質。

## 使用方式

### GUI（建議）

直接雙擊 `Seal_Open_Coding_V1.3.bat`。視窗及標題列會使用 `seal_open_coding_icon.png` 作為海豹牌 icon。在視窗中：

1. 加入一份、多份訪談文本，或加入整個資料夾。
2. 選擇研究指引文檔。
3. 選擇 CSV 輸出資料夾。
4. 設定模型與每段約略字數後，按「開始 Open Coding」。

可在同一次工作加入多個檔案與多個資料夾；資料夾會遞迴尋找 `.txt`、`.md`、`.docx`，去除重複路徑後逐篇處理。每篇立即寫成獨立 CSV，單篇失敗會記錄後跳到下一篇。未勾選覆寫時，重新執行會跳過已有 CSV，適合中斷後接續。若不同資料夾含同名逐字稿，工具會自動在輸出檔名加入穩定識別碼，避免互相覆蓋。

GUI 分析期間會要求 Windows 防止因閒置而自動睡眠，批次結束、停止或關閉程式後即恢復原設定；不會強迫螢幕保持亮起。手動睡眠、關機或闔上筆電上蓋仍可能中斷工作，因此整晚執行時應接上電源，並確認闔蓋動作不會讓電腦睡眠。Ollama 與 GUI 都必須保持執行。

主畫面右上角會顯示本次批次的「已執行 HH:MM:SS」，完成或停止後保留最終時間。批次結束通知會列出總執行時間、成功完成、跳過既有結果與失敗的文檔數；即使只有部分文檔成功，也能直接閱讀已完成的 CSV。

### 閱讀 Coding 結果

分析完成後按主畫面的「閱讀結果」，即可在程式內逐頁閱讀，不需要開啟 Excel、文字檔或其他 CSV 軟體。第一頁是文本簡介（受訪者／角色、明確年齡、身分脈絡、可觀察特質與訪談摘要），中間每頁是一筆原始文字、code、`why_this_code`、來源文件與 segment，最後一頁是「海豹覺得的研究方向」，列出可能發現、研究機會、相關 code 與原文語證。所有內容都保存在同一份 CSV。

「閱讀結果」會優先開啟本次新產生或覆寫的 CSV；也可在閱讀畫面按「開啟 CSV…」載入過去的結果。多份 CSV 會透過上方的結果檔案選單切換，畫面仍一次只顯示一筆 coding。

V1.3 的內建閱讀器採用與獨立 Seal Code Reader 相同的書本海豹圖示、卡片式版面、各欄位捲軸、上一頁／下一頁與頁碼跳轉，也可按 `Ctrl+O` 手動載入其他 CSV。兩者都是唯讀介面，不會修改 CSV；差別是內建版能在分析完成後直接載入本次結果，獨立版則適合交給沒有安裝 Python、Ollama 或主分析工具的同學。

長篇原文會先按句子切分，再組成約 5,000 字且最多 10 句的小批次逐批送給本機模型。研究指引也會隨每一批重新提供。GUI 的「前後文搜尋上限」預設為 6，表示海豹可查看命中句前後各最多 6 句；這只是搜尋邊界，不是固定輸出長度。

V1.3 會在 code 精選完成後再做一次「語證範圍校正」，重新選擇參與者實質陳述所在的主句與必要 `supporting_segment_ids`，並把逐字定位結果寫入 `evidence_context`。重點只在命中句時可只顯示一句；情境、操作、反應、比較與評價跨越較長對話時則可保留 5 句以上。它不再固定取前後句，每個被保留的句子都必須直接協助理解該 code。`context_before`、`context_after` 與 `full_context` 仍保留為稽核資料，但 Reader 優先顯示校正後的相關範圍。

`+` 與 `-` 開頭現在會保留為不同的通用發言標記，但不會被工具擅自認定為受訪者；研究角色仍由 codebook、明確 speaker 標籤與對話內容共同判斷。日期時間中的冒號也不再被誤當作講者分隔符。

行首 `+`／`-` 只會記錄為通用講者標記，不會被推論成受訪者或訪員。只有 `受訪者：`、`訪員：` 等明確角色標籤才會用於角色過濾；未標明角色時會依發言內容排除提問、操作說明與引導語。

若模型在某個大區塊中改寫證據、導致無法精確定位，程式會自動把該區塊對半拆小後重試。最小片段仍無法定位時只會略過該片段，其他已完成區塊仍會正常寫入 CSV，不會讓整份訪談失敗。

模型請求 timeout 也採用同樣的局部恢復策略，但不會用相同大 prompt 苦等重試：區塊逾時後立即對半拆小；若拆到單一句仍持續逾時，才略過該句並繼續後面的段落。聚焦篩選逾時會改採 `analytic_score`，文本簡介或研究方向逾時則使用保底內容，因此不會因最後階段 timeout 丟掉整篇已完成的 coding。

GUI 預設勾選「精選重要 code（建議）」。工具先產生貼近原文的初始候選，再從整份訪談層級比較候選，只保留受訪者獨特觀點、條件式選擇、反覆行為、因應策略、矛盾、界線與轉變，並去除一般作息、理所當然的事實及重複弱證據。取消勾選可輸出全部初始 codes。

「每篇至少 code 數」是品質合格候選的目標下限，預設為 10。V1.3 只從研究相關性與語證合格、且推論風險可接受的候選補足；合格候選本來就少於下限時，會保留全部合格候選並警告，不再拿無關 code 湊數。設定為 0 表示不設最低數量。

設定為 0 時，若整篇沒有通過品質門檻的候選，CSV 可以只有首頁與研究方向尾頁而沒有 coding 頁。每份結果首頁都會顯示「🦭 海豹的 Code 數量說明」：列出可定位初始候選數、通過品質門檻數、最後保留數與設定下限；若少於下限，也會說明未補足是因為品質合格候選不足，並標記有多少片段因持續逾時或無法可靠定位而略過。這段說明由程式依實際計數產生，不讓模型猜測失敗原因。

V1.3 不使用「因為、拒絕、反覆」等關鍵字直接加分。每個 code 分別評估 `research_relevance`、`behavior_pattern`、`evidence_strength`、`opportunity_potential` 與 `inference_risk`，再計算 0–100 的 `analytic_score`。研究相關性與語證是先決門檻，句型完整但偏離研究題目的生活故事不會只因含因果詞而得到高分。短答、訪員功能介紹與角色錯置會被拒絕或提高推論風險。完整撰寫方式見 `CODEBOOK_GUIDE_V1.3.md`。

尾頁會把「可能發現」與「研究機會」分開。每個方向還必須提供一個同時逐字出現在方向與引用 code 中的 `shared_concept`；若模型引用存在但語意不相干的 candidate，工具會拒絕該方向，避免研究方向與語證錯配。

## Code 篩選規則與存放位置

海豹不是只依一個總分直接截斷結果，而是依序經過下列階段：

1. **初始候選**：模型逐段尋找與研究問題相關的經驗、行為、評價、條件、矛盾、因應策略與研究機會。人口資料、一般作息、訪員說明、無理由短答及理所當然的事實原則上不產生 code。
2. **原文定位**：每筆候選必須提供存在於逐字稿的 `segment_id` 與逐字 `evidence_quote`。程式找不到唯一原文時會拒絕該筆，避免把 code 配到錯誤段落。
3. **角色與推論檢查**：訪員話語不能作為主要命中句；代述者的觀察不能改寫成被描述者的內在動機；原文沒有因果時不能自行補造因果。
4. **五維評分**：每筆分別評估 `research_relevance`、`behavior_pattern`、`evidence_strength`、`opportunity_potential` 與 `inference_risk`，範圍皆為 0–4。總分公式為 `相關性×10 + 行為模式×7 + 語證強度×6 + 研究機會×2 − 推論風險×8`，最後限制在 0–100。
5. **品質門檻**：只有 `research_relevance >= 2`、`evidence_strength >= 2` 且 `inference_risk <= 2` 的候選能進入主要結果。總分高但未通過門檻者仍不會保留。
6. **整篇聚焦精選**：比較整份訪談的合格候選，優先保留獨特觀點、具體或條件式行為模式、接受／拒絕條件、張力、轉變與較強語證，並移除重複、太細或與研究問題無關的 code。有多個高價值 code 時可以一起保留，不是只能留下最低設定數量。精選模式的自適應上限約為初始候選的 35%，通常最少容許 8 筆、最多 40 筆；若使用者設定的最低數量更高，上限會隨之提高，但仍只補入通過品質門檻者。取消「精選重要 code」則不套用此整篇精選上限。
7. **最低數量補足**：「每篇至少 code 數」只從已通過品質門檻的候選依分數補足。合格候選不足時寧可少於設定值，也不會用低相關或高推論風險的 code 湊數。

規則分別位於：

- **研究主題、角色、相關／無關範圍、想找的行為模式與正反例**：執行時在 GUI 選擇的研究指引／codebook 文件。這是每項研究最應優先修改的地方。
- **Codebook 寫法**：[`CODEBOOK_GUIDE_V1.3.md`](CODEBOOK_GUIDE_V1.3.md)。這是撰寫指南，不會自動成為分析規則；仍需在 GUI 選取實際研究使用的 codebook。
- **通用初始 coding prompt、五維公式、品質門檻、原文定位、聚焦精選與語證範圍校正**：[`open_coding.py`](open_coding.py)，主要位於 `build_prompt()`、`quality_dimensions()`、`quality_eligible()`、`validate_codings()`、`_focused_select()` 與 `refine_evidence_ranges()`。
- **最低 code 數、前後文搜尋上限等可調設定**：[`open_coding_gui.py`](open_coding_gui.py)，執行時可直接由 GUI 調整。

如果覺得 code 太細、偏題、漏掉特定行為模式，推薦先修改研究用 codebook，而不是直接改 `open_coding.py`。可先收窄研究現象、補充角色規則、列出應排除內容，並加入 2–3 個符合實驗室分析習慣的好／壞例子。只有要改所有研究共同使用的安全門檻、計分公式或篩選機制時，才建議修改程式碼。

## 海豹的正確用法

海豹適合在深夜、離開電腦前，或研究者忙著處理其他工作時，使用本機 Ollama 自動整理「初步」Open Coding。它能先切分長逐字稿、保留上下文、定位語證、整理候選 code 與可能研究方向，讓研究者隔天從較有結構的材料開始閱讀。

海豹不是代替研究者做完分析，也不應成為唯一的 codebook 或結論來源。建議研究者逐筆複核原文與 `why_this_code`、查看未被選中的段落與反例、比較不同受訪者、撰寫分析 memo，並依研究團隊討論修訂 code。尾頁的可能發現只是後續分析假設，不是質性研究結果。

主畫面右上角每 2 秒更新 CPU、NVIDIA GPU 與 VRAM 使用率，不需要額外安裝監控套件；未偵測到 `nvidia-smi` 時會顯示「GPU 未偵測」。執行紀錄保留原本專業 log，並在分析區塊、拆小重試、聚焦初選、跨批比較、完成與錯誤等階段追加綠色海豹旁白。分析期間還會每 9 秒從 36 種海豹動態中輪播。底部狀態列每 420 毫秒以 `. → .. → ... → .. → .` 顯示動畫；進入聚焦篩選後會改顯示「篩選階段 初選 x/y」、「最終比較」或「分數回退」，而不再停留在最後一個分析區塊。

### 命令列

先啟動 Ollama 並下載模型：

```powershell
ollama pull qwen3:8b
```

分析單一逐字稿：

```powershell
python open_coding.py interview01.txt --guide research_guide.docx --model qwen3:8b
```

分析整個資料夾（每份文檔各輸出一個 CSV）：

```powershell
python open_coding.py .\transcripts --guide .\research_guide.docx --output-dir .\coding_output
```

以命令列調整每個命中句前後可搜尋的最大句數（1–20）：

```powershell
python open_coding.py .\transcripts --guide .\research_guide.docx --context-radius 10
```

預設不覆寫已存在的 CSV，因此中斷後可重新執行並跳過已完成的訪談。若要重做：

```powershell
python open_coding.py .\transcripts --guide .\research_guide.docx --overwrite
```

## 研究指引怎麼寫

研究指引可用一般文字，不必先定義完整 codebook。建議包含：

1. 研究目的與研究問題。
2. 訪談情境及受訪者角色。
3. 想特別留意的行為、感受、原因、阻礙或策略。
4. 排除規則，例如不分析訪員說明、寒暄或個資。
5. code 命名偏好與 2–3 個例子（若有）。

這仍是「研究焦點引導的 open coding」，不應把輸出視為無偏誤或可取代研究者判斷。建議人工複核低信心結果，並抽查未被標記的段落。
