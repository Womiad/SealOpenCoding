# 研究目的
本研究想了解個人短影音創作者在為影片挑選配樂與音效時，如何在版權風險、製作時間與
觀眾反應之間做取捨；遇到哪些阻礙；以及這些選擇如何回頭改變他們的創作流程與作品樣貌。
不處理授權金額的具體數字，也不推測平台演算法的運作方式。

# 角色與資料規則
逐字稿以「訪員：」與「受訪者：」標示。只有受訪者自己的實質經驗、想法、行為或評價
可以成為 code 的主要依據；訪員的提問、情境說明與重述只能作為理解上下文的材料。
受訪者轉述平台公告或他人說法時，要與其本人的直接經驗區分開來。

# 優先尋找的行為模式
- 情境／觸發 → 行動／策略 → 結果或意義（什麼情況下會怎麼做、為什麼、後來如何）
- 有條件的選擇：「除非…才會…」「如果是…就改成…」
- 反覆出現的做法、前後矛盾、態度轉變、自己劃出的界線
- 為了迴避風險而付出的代價，以及受訪者如何評價那個代價

# 可形成研究機會的訊號
- 想做到卻做不到的事、被工具或平台流程擋住的地方
- 願意接受或明確拒絕某種做法的條件
- 自己動手與交給工具／平台之間的分界
- 對同一件事，不同受訪者給出相反判斷的地方

# 排除規則
- 訪員的提問、功能介紹、重述與總結
- 「嗯」「對」「好」這類沒有內容的簡短回應
- 沒有理由也沒有具體經驗的一般背景敘述（例如只說做了幾年）
- 需要大幅推測受訪者動機才成立的詮釋

# Code 結構
每個 code 是一個能獨立閱讀的分析句，包含情境、受訪者的行動或理由，以及結果或意義。
不要只寫主題標籤：不要寫「版權」，要寫「被下架過一次之後改用平台內建音樂，代價是
影片聽起來與別人雷同」。
